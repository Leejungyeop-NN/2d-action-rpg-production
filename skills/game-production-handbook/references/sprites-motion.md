# 스프라이트·모션·시간축

## 먼저 분리할 것

생성 영상의 FPS/길이, 추출 FPS, 클립 재생 주기, 게임 시뮬레이션, 화면 렌더링, 출력 LOD를 별도로 기록한다. 12fps 모션을 쓴다고 화면 전체를 12fps로 제한하지 않는다. 반대로 고정 화면 FPS가 알파 테두리·원본 블러·프레임 변형을 고치는 것은 아니다. 수치는 프로젝트 검수로 결정한다.

프레임 마스터와 배포 샘플은 다른 자산이다. 샘플링 비교는 같은 동작 길이·화면 크기·시작 위상으로 수행한다. 프레임 수를 줄이면서 동작까지 빨라지게 비교하지 않는다. 원본에 없는 중간 프레임을 보존됐다고 주장하지 않는다.

## 동작 계약

주체·무기·방향·카메라·루트·접지·예비/활성/회수·루프·공격 이벤트·여백을 적는다. 분리 합성 파이프라인에서는 몸/휴대 무기와 투사체/마법진/타격광을 별도 제작한다. 몸 모션에 외부 FX가 구워지면 방향·속성·피격 시점 변경이 어려워진다.

|동작|핵심 검사|대표 수정|
|---|---|---|
|Idle|발 접점 고정, 호흡, 첫/끝 위상|발이 걷는 구간 제거·안정 구간 선택|
|Run|진입과 반복 구간 분리, 자연스러운 보행|중립 프레임 매번 반복 금지, 평행 발 트랙|
|Jump|도약/공중/착지 연결, 다리 걸림·급변 없음|이미지에 구워진 이동 정합, 물리 높이 분리|
|Attack|무기 궤적과 접촉, 다음 동작 연결|발사/타격 이벤트 재정렬, 역할별 후속타|
|Hit|판정·시각 반동·행동 경직 분리|Idle이 즉시 덮지 않는지 확인|
|Death|죽음 자세 완료와 퇴장 순서|단순 축소/찌그러뜨리기로 대체하지 않음|

모든 게임이 같은 3연격/사망 페이드/보스 시체를 가져야 하는 것은 아니다. 승인된 동작 설계를 따른다. 점프 물리 위상, 경직 홀드, 빙결 프레임 고정은 임의 가변 속도와 구분해 이벤트로 기록한다.

## 추출·피벗·루프 보정

셀 사각형의 중앙/하단이 실제 몸 중심/접점이라고 가정하지 않는다. 알파 경계·발/받침·무기 끝을 측정한다. 첫/끝과 의심 프레임의 이웃 자세를 접촉 시트로 보고 실제 속도로 재생한다. 원본 재추출→안정 구간/프레임 선택→정합→필요 시 재생성 순으로 비용과 손실을 비교한다. 잘라낸 파생본을 만들더라도 원본 프레임은 남긴다.

원본에서 루트 이동이 구워져 있고 게임도 이동시키면 이중 이동이 된다. 제자리 모션이 의도라면 프레임 좌표를 맞추고 월드 XY·점프 Z를 게임에 맡긴다. 진짜 root-motion 설계인 다른 프로젝트에는 이 규칙을 무조건 적용하지 말고 이동 책임을 먼저 확인한다.

밝고 어두운 배경에서 알파 구멍·키색 테두리·흰 박스·투명 빈 프레임을 확인한다. 모션 전환 때 로드되지 않은 프레임을 그리는 문제와 원본 이미지 문제를 구분한다. 동일 주체의 Idle/이동/공격 사이 크기와 피벗이 흔들리지 않아야 한다.

## 출력과 검수

FPS와 이미지 배율을 독립 축으로 내보내고 셀·피벗·sourceRect·루프/이벤트·프레임 매핑을 갱신한다. 픽셀 아트의 보간 번짐을 막는 최근접/point 정책도 비정수 축소의 정보 손실까지 없애지는 않는다. 실제 DPR/카메라/좌우 반전/렌더링 크기에서 확인한다. 논리 hitbox나 월드 이동 거리를 이미지 LOD와 같이 줄이지 않는다.

비교 결과에는 어떤 동작·구간·조건을 실제 재생했는지 남긴다. 접촉 시트만 확인했으면 시간적 연결까지 통과했다고 보고하지 않는다.
