# 게임 UI/UX · 업무 흐름과 시각 위계

## 레퍼런스를 작업 구조에 맞춘다

현재 플레이어의 업무와 주목 대상을 먼저 정한다. 단일 캐릭터 게임의 장비창은 다인 관리의 답이 아닐 수 있다. 파티/필터/세팅은 다인 게임, 전투 단축키/위험/방 이동은 해당 액션 장르 등 기능별로 비교한다. 웹 구현이라는 이유로 큰 카드·과도한 CTA·대시보드식 상시 정보 나열을 기본값으로 두지 않는다.

장비 대상 변경은 장비 업무를 유지해야 하고, 성장 관리와 출전 편성은 다른 목적이다. 진입→대상/분류 선택→상세→실행→복귀를 써 보고 대상·필터·스크롤·선택 맥락이 유지되는지 확인한다. 관련 기능을 같은 창에 몰아넣는 것이 통합 UX는 아니다.

## 치수·밀도 시스템

논리 화면, 종횡비/안전영역, 입력 장치, 플랫폼과 확대 정책을 먼저 확인한다. 고정 가로 게임을 임의의 세로 반응형으로 바꾸지 않는다. 제목/본문/설명/숫자/보조 라벨과 주요/보조/필터/슬롯/아이콘 버튼을 역할별 토큰으로 잡는다. 보편적인 게임용 px 상수를 발명하지 말고 실제 크기에서 비교한다.

이미지 패널/버튼은 시각 정체성 수단이며 모든 버튼에 씌울 의무가 아니다. 프레임에 아이콘/문구가 꽉 차면 여백이나 프레임 사용 자체를 검토한다. 화살표까지 묶은 중앙 정렬 때문에 문구만 치우치지 않는지 본다. 선택 상태는 배경색 덩어리 추가보다 프로젝트의 아이콘/슬롯 문법과 맞춘다.

같은 화면의 상태 변화에서는 설명 자리·행동부가 흔들리지 않게 한다. 서로 다른 목적의 모든 패널을 같은 큰 크기로 통일하지 않는다. 의미 없는 빈 공간도 과밀만큼 결함이다. HP/MP 원형, 버튼 높이, 동료 초상 방식은 프로젝트와 레퍼런스의 실제 선택이며 보편 규칙이 아니다.

## 필수 상태와 오버플로

텍스트가 소유 컨테이너를 벗어나는 결과를 허용하지 않는다. 웹에서는 grid/flex의 min-width:0, 축소 가능한 열, 적절한 줄바꿈/말줄임을 함께 확인한다. 접힌 선택값은 말줄임+전체 조회, 열린 옵션은 여러 줄을 허용하는 등 역할별로 다르게 처리한다. 새 입력 제한만으로 기존 저장값/다국어 확장 길이가 해결되지는 않는다.

기본, 긴 이름/소속, 빈 목록, 미합류/잠김, 비용 부족, 최대 강화, 속성 선택 전후, 펼친 드롭다운/아코디언, 툴팁, 하위 모달을 확인한다. 비용·확인·뒤로·닫기 등 필수 행동은 스크롤에 사라지지 않게 하고 설명/목록이 우선 스크롤되게 한다. 미니맵 등 HUD가 모달 닫기를 막지 않게 레이어/포커스 계약을 검수한다. 키보드/패드 탐색과 포커스 복귀도 실제 조작한다.

## 게임의 정보 배치

전투 HUD는 지금 판단/입력할 정보, 가방/장비는 소유/교체와 재화, 성장 화면은 비용/변화량을 담당한다. 모든 재료·자동저장·슬롯 정보를 상시 HUD에 올리지 않는다. 공방과 전투의 목적이 같으면 구성요소를 공유하되 문맥에 맞는 데이터와 동작을 연결한다. PC 전용 화면에 큰 터치 점프 버튼을 붙이지 않는다. 모바일은 해당 조작 문법을 별도 설계한다.

캐릭터 식별에는 적합한 스탠딩/초상을, 실제 전투 동작 조회에는 Idle/기술 재생을 쓴다. 재료 수급 안내는 활동 분류에서 목적지로 연결하며 미래 모든 지역을 한 번에 나열하지 않는다. 원산지·현재 거주·편성 가능성을 같은 필터로 오인하지 않는다.

## 완료 판단

실제 레퍼런스와 같은 비율로 놓고 밀도·여백·타이포·선택 강조·실행 위치를 비교한다. 문서상 토큰뿐 아니라 실제 계산 스타일/스케일을 본다. 닫힘·펼침·긴 값·부족 상태를 캡처하고 진입/실행/복귀를 조작한다. 겹침 자동 검사는 실제 미감과 플로우 판정을 대신하지 않는다.
