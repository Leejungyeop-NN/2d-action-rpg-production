# 게임디자인 · 경험, 진행, 경제

## 작업 계약

먼저 무엇을 즐기게 할지 정한다. 핵심 행동, 그 행동에 필요한 판단, 성공/실패의 피드백, 다음 선택으로 이어지는 보상을 연결한다. 기능 목록이나 메뉴 수를 코어루프라고 부르지 않는다. 이미 돌아가는 게임은 실제 저장·전투·보상 경로를 읽어 문서상 기능과 대조한다.

전투의 초 단위 루프, 탐사의 분 단위 루프, 캠페인의 시간 단위 루프를 구분한다. 예: 위치/위험 읽기→시전→회피→명중 / 준비→탐사→보상→제작 / 발견→관계 변화→새 목표. 새 기능이 어느 루프를 강화하는지 설명하지 못하면 범위를 다시 검토한다.

## 분량과 콘텐츠

필수 경로, 주요 선택 콘텐츠, 수집/숙련, 재도전을 나눠 시간 예산을 만든다. 서로 포함된 시간을 이중 합산하지 않는다. 초견 관찰·숙련 플레이·자동 시뮬레이션을 따로 기록한다. 반복 파밍·이동·대기 시간을 늘려 목표 플레이타임을 채우지 않는다. 단계별로 새 행동/환경/관계/보상이 생기는지 본다.

색/속성 조합 140개는 손으로 설계한 기술 140개와 다르고, 장면 키 70개는 삽화 70장과 다르다. 모델 변형과 행동 패턴, 맵 모듈과 임무 배치도 별도 수량으로 센다. 가장 비싼 신규 원화/모션/보스와 실제 재사용 가능한 분량을 분리해 범위를 산정한다.

## 스킬과 난이도

목적·입력·대상·범위·자원·지속·쿨타임·상태·중단/실패 조건을 먼저 정의한다. 스킬 설명, 실제 판정, 모션 이벤트, FX를 같은 명세로 연결한다. 보호 캐릭터의 모든 스킬을 보호막으로 만드는 식의 기능 중복을 역할 정체성과 혼동하지 않는다.

위험 예고의 실제 면적과 타이밍에 피해가 있는지, 같은 원근선의 시각적 명중과 판정이 어긋나는지 확인한다. 적 체력/수만 늘리는 난이도와 전술 변화는 구분한다. 파티 AI가 피할 수 없는 장판·문·밀집 프랍으로 어려움을 만들지 않는다. 상태이상 대상 팀과 면역, 단일 대상일 때의 동작도 검사한다.

## 경제·성장

각 자원에 공급 활동/빈도/수량, 소비 행동/비용, 해금 시점, 부족 시 복구 경로를 양방향으로 적는다. 하나의 잔액에는 하나의 권위 원장을 둔다. 실패한 거래가 일부 재료만 차감하지 않게 후보 상태에서 검증 후 확정한다. 보호/예약 장비, 가방 부족, 최대 성장, 최초/반복/회상 보상, 재로드 중복을 검사한다.

기술 기본량·공격력 기반 계수·레벨 배수·방어·속성 반응·최종 피해를 분리한다. 적용 순서와 가산/곱산을 명시하고 대표 능력치로 검산한다. 강화 설명만 있고 전투 수치에 연결되지 않은 경우 완료가 아니다. 장비 세트는 실제 같은 대상의 장착 인스턴스를 세며 설명과 수치를 함께 확인한다.

제작→분해의 순환에서 자원이 무한 증가하는지, 회복 비용이 다음 성장을 막는지, 늦은 동료가 따라잡을 수 있는지, 실패 후 재출전할 수 있는지를 본다. 수급처 UI는 확장 가능한 활동 카테고리에서 목적지로 연결한다.

## 산출물과 검수

범위에 맞게 다음을 남긴다: 경험 목표 / 루프 / 기능·수치 계약 / 해금과 보상 / 데이터 정본 / 수용 기준 / 실제 관찰. 경제 열거 테스트는 거래 연결을, 수동 플레이는 이해·막힘·성취를 확인한다. 하나를 다른 하나의 합격으로 보고하지 않는다.
