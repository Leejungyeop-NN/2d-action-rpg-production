# 확장 리서치·검수·핸드오프

## 질문과 증거의 단위

‘던파 참고’ 대신 ‘드롭다운을 펼쳤을 때 장비 업무를 유지하는가’, ‘불기둥이 땅에 닿을 때 무엇이 남는가’처럼 판단할 질문을 정한다. 기존 프로젝트의 모든 대상 화면/스킬을 범위표로 만들되 한 곳의 예시 수정으로 전체 개편을 완료했다고 하지 않는다.

공식 자료는 기능/용어/권리, 유저 스크린샷은 밀도/펼침 상태, 초보·세팅 가이드는 실제 플로우/혼란, 영상은 시간/공격 인과에 강하다. 디시인사이드·아카라이브·루리웹·에프엠코리아·레딧·블로그 등은 후보이며 사이트 이름을 채우는 것이 완료 조건은 아니다. 제품·플랫폼·버전·기기와 출처의 관점을 기록한다.

영상은 예비→발동→전달→접촉→잔류→회수를 실제 재생하고 본 타임코드/속도를 적는다. 검색 발췌, 정지 이미지, 재생 실패, 접근 불가는 각각 그대로 표시한다. 유저 콘셉트 UI·가이드의 빨간 박스·홍보 이미지와 실제 게임 화면을 구분한다. 관찰/추론/우리 게임 제안을 다른 항목으로 기록하고 선택/탈락 이유를 남긴다.

## 공개 자산과 권리

공격/접촉/균열/광선/감정 등 역할별로 후보를 모은다. 제작자·원문 URL·라이선스·상업 이용/변형/재배포/표기 조건·다운로드 원본을 기록한다. 무료라는 말만으로 CC0나 오픈소스로 분류하지 않는다. 레퍼런스 게임의 자산 추출/무단 반입과 시각 분석은 다르다. 권리가 불명확하면 실제 반입은 보류하고 다른 후보를 찾는다.

고해상도인데 캐주얼한 후보와 저해상도지만 적합한 모션을 비교한다. 후자는 편집/업스케일 후보이지 자동 합격이 아니다. 후보 풀을 넓히되 다운로드 수를 성과로 삼지 않는다. 현재 세션의 다운로드/생성 승인을 다른 세션이나 다른 서비스의 영구 권한으로 가져오지 않는다.

## 과업 기록의 최소 계약

작은 수정에는 간단한 기록으로 충분하다. 전면 개편에는 다음 계약을 명세한다.

- 현재 문제와 사용자 목표, 포함/제외/보류, 누적 요구 ID
- 현재 정본·저장·자산과 충돌하는 부분, 영향 범위
- 실사용 근거와 관찰/제안 구분, 대안과 선택 이유
- 진입/행동/결과/복귀 또는 전투/연출 시간표
- 입력·데이터·아트·좌표·레이어·타이밍·로딩 계약
- 수용 기준·검수 조건·실시 결과·미결정·다음 담당자 시작점

계획만 요청된 경우 구현으로 확대하지 않는다. 설계가 필요한 작업에서 구현부터 하고 나중에 근거를 붙이지 않는다. 새 피드백은 취소/정정 여부를 읽고 기존 요구를 누락하지 않게 반영한다.

## 네 종류의 검수

규칙 테스트(상태/거래/보상), 시각 재생(밀도/가림/타이밍), 플레이 관찰(이해/선택/막힘), 환경 검증(실제 OS/기기/파일 진입)을 분리한다. HTTP 성공은 Windows 직접 파일 실행의 증거가 아니다. 자동 플레이는 초견 사용자의 재미 평가가 아니다. 정지 캡처는 루프/박자 검수의 증거가 아니다.

수행할 수 없는 항목은 제한으로 남기고, 가능한 독립 작업을 진행한다. 검수용 강제 진행·합성 저장·렌더 override가 배포에 들어가지 않게 한다. 사용자 탭/실플레이 저장에 시드를 넣지 않는다. 재현할 때 제품과 QA 어댑터를 구분한다.

## 인계와 유지

기준 버전·승인 상태·실행/빌드 명령·정본 경로·변경과 이유·관련 자산/출처·검수/미수행·미결정을 연결한다. 원장은 수치의 두 번째 수작업 정본이 되지 않게 소스 추출/해시를 활용한다. 이전의 ‘최신’ 문서를 계속 쌓지 말고 현재 입구와 역사 기록을 분리한다.

스킬에 담은 과거 기법은 판단 자료다. 프로젝트의 최신 사용자 지시/현행 계약/증거가 바뀌면 이 자료를 갱신한다. 특정 IP 이름·12fps·글자 크기·도구·파티 수를 다른 프로젝트에 옮겨 강제하지 않는다.
