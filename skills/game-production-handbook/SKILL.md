# 2D Action RPG Production · 제작 지침

게임의 **선택·행동·결과·다음 선택**을 기준으로 제작한다. 웹으로 구현해도 플레이 화면을 SaaS 대시보드처럼 설계하지 않는다. 장르·플랫폼·현재 사용자의 의도를 우선하며, 특정 레퍼런스의 외형을 모든 게임에 강제하지 않는다.

## 적용 범위와 한계

가장 적합한 대상은 **스프라이트 기반 2D 액션 RPG·벨트스크롤**, 특히 한국어 서사·자율 동료·인벤토리·속성 기술을 다루는 제작/검수다. 인접한 2D 장르에는 필요한 모듈만 조정해 적용한다. 모든 게임 제작이나 출시 품질을 보장하는 스킬이 아니다.

3D 리깅/카메라/셰이더, VR, 네트워크/경쟁 멀티플레이, 엔진별 구현, 법률 자문·상업 성공 예측은 검증 범위 밖이다. 그런 요청에서는 범위를 먼저 설명하고 공통 원칙과 전문 작업을 구분한다. 한국어 중심 지침이며 다른 언어의 문체 품질은 검증하지 않았다. [적합성·한계](references/scope.md)를 참고한다.

## 시작과 범위

작업 루트의 지침, 현재 기획/정본 소스, 관련 검수 증거를 확인한다. 요구가 단순하면 해당 부분만 읽고 고친다. 전면 개편이나 불확실한 표현 설계는 누적 피드백을 정리하고 **리서치 → 설계/명세 → 작은 구현 → 실제 검수 → 확대 적용**으로 진행한다. 설계만 요청되면 구현·생성·배포로 넘어가지 않는다.

새 피드백은 취소/정정/추가를 구분해 명세와 검수 범위에 반영한다. 사용자의 예시는 원리를 이해하는 단서이며, 그대로 모든 화면에 복사하는 정답이 아니다. 승인 의도와 실제 구현이 다르면 차이를 기록하고 해결한다. 제안·현행 구현·역사적 실험·사용자 승인을 섞지 않는다.

## 제작 판단의 핵심

- **서사:** 처음 보는 사람이 목표와 인과를 이해하는가. 대사는 직전 행동/말에 반응하는가. 지식·소유·합류 상태가 일치하는가.
- **그림:** 같은 인물의 외형을 보존하면서 매체에 맞는 구도/행동을 만드는가. 입력 이미지의 역할과 우선순위가 명확한가.
- **모션:** 루트·접지·위상·이벤트가 연결되는가. 원본/추출/재생/시뮬레이션/렌더링 시간을 구분했는가.
- **전투 표현:** 시전·전달·지형·피격·지속·종료가 무기와 기능을 설명하는가. 색과 크기 변경만으로 역할 차이를 대신하지 않았는가.
- **UI:** 현재 업무를 유지하는가. 정보 위계·밀도·선택·행동 위치가 일관되고, 펼침/긴 이름/부족/최대 상태도 컨테이너 안에서 처리되는가.
- **디자인:** 보상과 소모, 성장과 어려움, 반복과 서사 동기가 실제 플레이로 연결되는가. 데이터 개수를 경험의 양으로 오인하지 않는가.

## 완료와 인계

관련 기능을 실제 맥락에서 검수한다. 모션/FX/전환은 정지 그림만으로 통과시키지 않는다. 규칙 테스트·실제 시각 재생·플레이 체감·운영 환경 검증을 구분한다. 사용할 수 없는 도구나 보지 못한 영상은 한계로 남기고, 성공했다고 쓰지 않는다.

결과에는 변경/선택 이유, 정본과 관련 파일, 수행한 검수와 미수행 범위, 미결정/다음 행동을 남긴다. 실행하지 않은 생성 템플릿을 실제 요청 기록으로, 합성 QA 진행을 실제 사용자 완주로 보고하지 않는다.

이 스킬은 생성 비용·다운로드·게시·배포·외부 업로드 권한을 부여하지 않는다. 해당 과업에서 이미 주어진 권한을 존중하고 부족한 부분만 확인한다. 사용자 실플레이 저장·탭·원본 마스터는 검수 편의로 바꾸지 않는다. 고정 FPS/해상도/글자 크기/동료 수/도구 우선순위는 프로젝트별 계약이며 공통 상수가 아니다.
